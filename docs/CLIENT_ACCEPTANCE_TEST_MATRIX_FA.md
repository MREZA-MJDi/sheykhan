# ماتریس تست پذیرش کارفرما — دوره، کلاس، ویدئو و جلسات آنلاین

این سند برای اجرای تست روی محیط آزمایشی/Stage و تأیید کارفرماست. هیچ‌یک از تست‌های حذف یا Seed را روی پایگاه دادهٔ Production اجرا نکنید.

## ۱. دادهٔ آزمایشی و Seed

- [ ] در محیط محلی یا Stage خالی، migrationها اجرا و Seedهای مجاز همان محیط اعمال شوند.
- [ ] LearningSeeder فقط وقتی APP_ENV=local است توسط DatabaseSeeder فراخوانی می‌شود؛ روی Production به‌صورت پیش‌فرض دادهٔ آموزشی نمایشی تزریق نمی‌شود.
- [ ] سه دورهٔ نمونهٔ ریاضی هفتم، علوم هشتم و آمادگی تیزهوشان نهم دیده شوند.
- [ ] هر دوره دو فصل داشته باشد: فصل اول ۴ درس و فصل دوم ۵ درس.
- [ ] فقط درس اول فصل اول پیش‌نمایش رایگان داشته باشد؛ ۸ درس دیگر قفل باشند.
- [ ] برای هر دوره کلاس مرتبط، مدرس، دانش‌آموزان نمونه و داده‌های رابطه‌ای از Seed موجود بررسی شوند.
- [ ] Seed دوباره اجرا شود و رکوردهای تکراری ساخته نشوند؛ تغییرات دستی محتوای موجود ناخواسته بازنویسی نشوند.

> هشدار: دستور migrate:fresh --seed تمام جدول‌های پایگاه دادهٔ انتخاب‌شده را حذف و از نو می‌سازد. فقط روی دیتابیس تست/محلیِ قابل‌پاک‌شدن اجرا شود، نه روی دادهٔ کارفرما.

دستور پیشنهادی برای محیط محلیِ قابل‌پاک‌شدن:

    php artisan migrate:fresh --seed

برای اجرای فقط داده‌های آموزشی روی دیتابیسی که migration آن قبلاً انجام شده است:

    php artisan db:seed --class=LearningSeeder

## ۲. ناوبری داشبورد مدیر آموزشگاه

- [ ] گروه‌های سایدبار با کلیک باز و بسته شوند و وضعیت گروه صفحهٔ جاری باز باشد.
- [ ] نشانگر رنگ هر گروه قابل تشخیص باشد.
- [ ] «دوره‌ها» مستقل از «کلاس‌ها و جلسات» دیده شود.
- [ ] «فروشگاه» مستقل از هر دو دیده شود و مسیر محصولات و سفارش‌ها را باز کند.
- [ ] کاربر بدون مجوز، لینک گروه یا عملیات غیرمجاز را نبیند و با URL مستقیم نیز پاسخ 403 بگیرد.
- [ ] محدودهٔ هر لینک وابسته به آموزشگاه درست بماند؛ تغییر شناسهٔ آموزشگاه نباید دادهٔ آموزشگاه دیگر را نمایش دهد.

## ۳. ایجاد و مدیریت دوره

- [ ] مدیر از «دوره‌ها ← ساخت دوره جدید» دوره‌ای با عنوان، شناسه، توضیح، سطح، وضعیت و قیمت بسازد.
- [ ] بعد از ساخت، مستقیماً وارد تنظیمات همان دوره شود و مجبور به جست‌وجوی دوره در فهرست نباشد.
- [ ] کاور دوره با JPG، PNG یا WebP تا ۱۰ مگابایت بارگذاری شود.
- [ ] فایل غیرتصویری یا فایل بیش از حد مجاز برای کاور رد شود.
- [ ] تصویر کاور در کارت دوره و صفحهٔ عمومی همان دوره نمایش داده شود.
- [ ] تریلر با MP4، WebM یا MOV تا ۲۰۰ مگابایت بارگذاری شود.
- [ ] تریلر ذخیره‌شده در پنل مدیر قابل پخش/حذف باشد.
- [ ] بارگذاری تریلر جدید، پس از موفقیت بارگذاری، تریلر قبلی را جایگزین کند؛ در صورت شکست بارگذاری، تریلر قبلی باقی بماند.
- [ ] تریلر در صفحهٔ عمومی دوره و بدون نیاز به خرید قابل پخش باشد.
- [ ] فایل‌های کمکی خصوصی دوره (PDF/ZIP/تصویر) از بخش جداگانهٔ فایل‌های دوره مدیریت شوند و به‌صورت عمومی در دسترس نباشند.

## ۴. فصل‌ها و درس‌های دوره

- [ ] مدیر فصل جدید بسازد و نام، توضیح و ترتیب فصل را ویرایش کند.
- [ ] مدیر درس را زیر فصل درست بسازد؛ نوع، عنوان، شناسه، خلاصه، مدت و محتوا ذخیره شوند.
- [ ] درس بتواند پیش‌نویس، منتشرشده یا آرشیوشده باشد.
- [ ] تیک «پیش‌نمایش رایگان» فقط برای درس‌هایی فعال شود که واقعاً قرار است بدون خرید قابل مشاهده باشند.
- [ ] مدیر بتواند جزئیات درس را ویرایش کند و بعد از ذخیره، مقادیر جدید در همان صفحه دیده شوند.
- [ ] فصل خالی حذف شود؛ فصل دارای درس به‌صورت مستقیم حذف نشود.
- [ ] درس فقط وقتی حذف فیزیکی شود که پیش‌نویس باشد و سابقهٔ پیشرفت/منبع آموزشی نداشته باشد.
- [ ] درس منتشرشده یا دارای سابقه حذف نشود؛ ابتدا آرشیو/پیش‌نویس و سیاست نگهداری سوابق بررسی شود.
- [ ] ترتیب فصل‌ها و درس‌ها در صفحهٔ عمومی و مسیر آموزش با ترتیب تنظیم‌شده مطابقت داشته باشد.

## ۵. کنترل دسترسی خرید و نمایش عمومی

با سه حساب مستقل تست شود: بازدیدکننده، دانش‌آموز بدون خرید و دانش‌آموز دارای ثبت‌نام/پرداخت کامل.

- [ ] بازدیدکننده، عنوان دوره، کاور، تریلر و ساختار فصل‌ها/درس‌ها را ببیند.
- [ ] بازدیدکننده فقط درس علامت‌خوردهٔ رایگان را از مسیر پیش‌نمایش باز کند.
- [ ] محتوای درس پولی برای بازدیدکننده و دانش‌آموز فاقد entitlement قفل بماند؛ دست‌کاری URL هم دسترسی ندهد.
- [ ] صرف ثبت سفارش یا ارسال رسید، دسترسی را فعال نکند.
- [ ] پس از ثبت پرداخت معتبر/تأیید نهایی و فعال‌شدن entitlement، دانش‌آموز محتوای دوره را ببیند.
- [ ] حساب والد فقط وضعیت دسترسی فرزند را ببیند؛ فایل خصوصی دوره در حساب والد به‌جای دانش‌آموز بارگذاری/نمایش داده نشود.
- [ ] لغو/بازپرداخت/غیرفعال‌شدن enrollment طبق سیاست دسترسی فعلی، پخش را قطع کند.
- [ ] تریلر عمومی از مسیر عمومی در دسترس باشد؛ فایل خام ویدئوهای درسی هرگز از URL عمومی ارائه نشود.

## ۶. SpotPlayer — ویدئوهای کامل و لایسنس

پیش‌نیاز تست واقعی: دسترسی معتبر پنل ناشر، اطلاعات اتصال سرور، شناسهٔ دقیق دوره در SpotPlayer و حساب دانش‌آموز آزمایشی.

- [ ] شناسهٔ SpotPlayer در تنظیمات همان دوره ثبت شود.
- [ ] ویدئوهای کامل هر فصل در پنل ناشر SpotPlayer داخل دورهٔ متناظر بارگذاری شوند؛ تریلر عمومی جایگزین این ویدئوها نیست.
- [ ] با حساب دانش‌آموزی که دوره را خریده، صدور لایسنس و پخش داخل صفحهٔ دوره بررسی شود.
- [ ] با حساب فاقد خرید، صدور لایسنس و پخش رد شود.
- [ ] درخواست تکراری، خطای ناشر، شناسهٔ اشتباه و پاسخ نامشخص بررسی شوند؛ در وضعیت نامشخص، لایسنس تکراری صادر نشود و مورد نیازمند بررسی دستی ثبت شود.
- [ ] لغو/انقضا/تغییر شناسهٔ دوره با لایسنس فعال بررسی شود؛ شناسهٔ دوره تا زمان تطبیق لایسنس‌های فعال قابل تغییر نیست.
- [ ] پخش واقعی، واترمارک، محدودیت دستگاه و رفتار مرورگر/موبایل با سیاست خریداری‌شدهٔ کارفرما تطبیق داده شود.

اتصال SpotPlayer در کد پروژه وجود دارد، اما موفقیت اتصال واقعی را فقط با اعتبارنامه و شناسهٔ پنل ناشر می‌توان تأیید کرد. تا انجام تست فوق، اتصال Production را «تأییدشده» تلقی نکنید.

## ۷. کلاس‌ها و برنامهٔ آموزشی

- [ ] کلاس برای یک آموزشگاه و دورهٔ معتبر ساخته شود و مدرس/پایه/سال تحصیلی/ظرفیت به آن متصل شوند.
- [ ] ویرایش عنوان، دوره، مدرس، ظرفیت و وضعیت ذخیره شود.
- [ ] ظرفیت کمتر از تعداد دانش‌آموزان فعال قابل ثبت نباشد.
- [ ] کلاس آرشیو و سپس بازیابی شود؛ roster، حضور و غیاب، برنامه و سوابق باقی بمانند.
- [ ] حذف دائمی فقط برای کلاس آرشیوشده و کاملاً خالی فعال باشد.
- [ ] کلاس دارای دانش‌آموز، برنامه، حضور و غیاب، تکلیف، آزمون، جلسهٔ زنده یا enrollment حذف فیزیکی نشود و در آرشیو بماند.
- [ ] برنامهٔ هفتگی و جلسات آینده با کلاس/مدرس صحیح ارتباط داشته باشند.

## ۸. Skyroom و ضبط جلسات

پیش‌نیاز تست واقعی: اتاق Skyroom واقعی و لینک معتبر صادرشده از پنل/سرویس کارفرما.

- [ ] جلسهٔ آنلاین با Provider برابر Skyroom و URL واقعی ذخیره شود.
- [ ] URL غیرمعتبر یا دامنهٔ ناسازگار رد شود.
- [ ] لینک ورود فقط برای نقش/دانش‌آموز مجاز و در بازهٔ زمانی مجاز نمایش داده شود.
- [ ] جلسه با حساب مدیر/مدرس و دانش‌آموز مجاز باز شود.
- [ ] جلسهٔ لغوشده یا خارج از زمان مجاز، امکان ورود عادی نداشته باشد.
- [ ] پس از پایان جلسه، فایل ضبط‌شده از پنل Skyroom دریافت و از بخش «ضبط جلسات» بارگذاری شود.
- [ ] ضبط به جلسه/کلاس صحیح متصل، بررسی و سپس منتشر شود.
- [ ] دانش‌آموز مجاز فایل ضبط‌شده را ببیند و حساب غیرمجاز به آن دسترسی نداشته باشد.
- [ ] لغو انتشار/آرشیو ضبط، دسترسی دانش‌آموز را قطع کند.

وضعیت یکپارچه‌سازی: لینک و زمان‌بندی Provider و گردش‌کار بارگذاری/انتشار ضبط در برنامه موجود است؛ ایجاد خودکار اتاق Skyroom و واردکردن خودکار فایل ضبط از پنل Skyroom در این نسخه تأیید نشده و در این ماتریس به‌عنوان قابلیت خودکار فرض نمی‌شود.
