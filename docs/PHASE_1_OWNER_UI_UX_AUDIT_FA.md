# فاز ۱ — ممیزی و یکپارچه‌سازی پنل Owner / Admin

**محدوده:** `/owner`، داشبورد اصلی ادمین/منشی، صفحات آموزشگاه، فرم‌ها، ناوبری، مسیرهای مدیریتی و مجوزهای مرتبط  
**شاخهٔ کاری:** `audit/phase-1-owner`  
**وضعیت:** پیاده‌سازی اولیهٔ طراحی و اصلاح مسیرهای دسترسی انجام شده؛ تأیید نهایی انتشار به اجرای CI و بازبینی بصری محیط زنده وابسته است.

## نقشهٔ دامنه

از `routes/web.php` و درخت فایل مخزن:

- ۹۶ تعریف Route در گروه اصلی Owner: ۴۴ GET، ۲۵ PATCH، ۲۵ POST و ۲ DELETE.
- ۴۰ فایل View در `resources/views/owner`.
- ۳۱ Controller زیر `app/Http/Controllers/Owner`.
- ۱۴ تست Feature با نام Owner/owner در `tests/Feature`.
- ۲۵ تعریف Route از `withoutScopedBindings()` استفاده می‌کنند؛ برای این مسیرها باید مالکیت و محدودهٔ آموزشگاه در Controller یا Service صریحاً کنترل شود.

## تغییرات اعمال‌شده در این شاخه

### Design System و اسکلت صفحات
- افزودن `resources/css/owner-design-system.css` به‌عنوان لایهٔ مستقل که بعد از استایل‌های legacy لود می‌شود.
- تنظیم تم روشن و یکپارچه برای Owner: رنگ‌های سطح، متن، Border، تأکید، موفقیت، هشدار، خطا، Radius و Shadow.
- یکسان‌سازی سلسله‌مراتب تیترها، فاصلهٔ بخش‌ها، هدر صفحات، کارت‌ها و حالت خالی در صفحات Owner.
- تعریف مقیاس پایهٔ متن و جلوگیری از نمایش متن‌های legacy با اندازه‌های ۷ تا ۱۰ پیکسل.
- یکسان‌سازی Input/Select/Textarea/File Input با ارتفاع، Padding، Focus، Placeholder، Disabled و خطای ورودی.
- استایل معنایی برای هشدار، موفقیت، خطا و اطلاع‌رسانی.
- تنظیم جدول‌ها، وضعیت‌ها، Pagination، نمودارها، Progress و الگوی Skeleton برای استفادهٔ صفحه‌های پویا.
- قواعد Responsive برای دسکتاپ، تبلت و موبایل، جلوگیری از Overflow و فاصلهٔ امن برای نوار ناوبری موبایل.
- رعایت `prefers-reduced-motion`.

### داشبورد و نمایش Featureها
- به‌روزرسانی کارت‌های میانبر برای نشان دادن مسیرهای دوره‌ها، دفتر مالی، مرکز سایت، محتوای سایت، مجله و اطلاعیه/ارتباطات.
- نمایش این میانبرها بر اساس Permissionهای متناظر؛ مسیر بدون مجوز نباید در داشبورد ظاهر شود.
- نگه‌داشتن مسیرهای آموزشگاه‌محور در انتخاب آموزشگاه، به‌جای هدایت بی‌قیدوشرط به اولین آموزشگاه.
- توسعهٔ `OwnerDashboardBackendContractTest` برای بررسی میانبرهای جدید و عدم نمایش مسیرهای فاقد مجوز.

### توضیح ورودی فرم‌ها
متن راهنمای عملی برای فیلدهای اصلی به این صفحات اضافه شده است:
- تنظیمات آموزشگاه
- ساخت تکلیف
- ساخت/ویرایش کلاس
- ساخت/ویرایش آزمون
- ثبت جلسه با اولیا
- محصولات و فایل‌های فروش
- مقاله و محتوای عمومی
- کتابخانهٔ فایل خصوصی
- بررسی رسید سفارش/پرداخت

این توضیحات باید با Validation سمت سرور هم‌خوان باشند؛ راهنمای UI جایگزین اعتبارسنجی سرور نیست.

## بازبینی Backend و Workflow

در نمونه‌های بررسی‌شده، مسیرهای اصلی از Middleware نقش/مجوز استفاده می‌کنند و Controllerها نیز در بخش‌های مهم کنترل مالکیت آموزشگاه و دادهٔ وابسته دارند؛ از جمله مدیریت افراد، کلاس، دوره و رسانه، حضور و غیاب، ثبت‌نام، آزمون، پیام‌ها، ضبط، پرداخت مدرس، محصولات، سفارش و showcase.

تست‌های موجود، قراردادهای مهمی از جمله scope داده‌های داشبورد، عدم دسترسی به کلاس/دورهٔ آموزشگاه دیگر، ظرفیت کلاس، ثبت‌نام تکراری، کنترل مجوز و ثبت‌نام امن را پوشش می‌دهند. این سند **ادعای اجرای همهٔ تست‌ها را ندارد**؛ CI باید روی Pull Request اجرا شود.
