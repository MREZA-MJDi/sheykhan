# ممیزی رابط عمومی و فرانت‌اند شیخان

**مبنای بررسی:** شاخه `main` در commit `dedeef6`  
**شاخه‌ی اصلاحات:** `fix/public-pages-seeder-and-ux-audit-20261023`  
**دامنه:** صفحات عمومی، ناوبری، محتوای local برای بررسی طراحی، تست‌های رندر و ساختار assetهای فرانت‌اند.

## نتیجه‌ی اجرایی

طراحی بازسازی‌شده‌ی صفحه‌ی اصلی، ناوبری، صفحه‌ی فهرست دوره‌ها و مجله در `main` وجود دارد. مورد جاافتاده، سِیدر جامع `PublicExperienceSeeder` است که اسلایدهای Hero، تصویرهای اصلی، محتوای عمومی، جزوه‌های نمایشی و داده‌های کاتالوگ را برای محیط local آماده می‌کند. این سِیدر در اجرای پیش‌فرض فقط در APP_ENV=local اجرا می‌شود؛ برای دیتابیس تست/استیجینگ با APP_ENV=production نیز اجرای دستی یک‌باره با فلگ صریح ممکن است، بدون فعال‌کردن سِیدرهای نمایشی در اجرای عمومی db:seed.

## تغییرات اعمال‌شده

- سِیدر تجربه‌ی عمومی از تاریخچه بازیابی شده و در اجرای عادی فقط در زنجیره‌ی APP_ENV=local اجرا می‌شود. روی دیتابیس تست/استیجینگ که APP_ENV=production دارد، فقط با فلگ یک‌باره‌ی SHEYKHAN_ENABLE_PUBLIC_EXPERIENCE_SEEDER=true و اجرای مستقیم همان کلاس فعال می‌شود؛ DatabaseSeeder یا سِیدرهای دیگر را فعال نمی‌کند.
- تست سِیدر با کاتالوگ local فعلی هماهنگ می‌شود: سه محصول موجود در سِیدر Commerce و سه ورک‌بوک عمومی. تست‌ها اسلایدها، بنرها، دوره‌ها، جزئیات محتوای عمومی، فیلتر فروشگاه و تکرارپذیری را بررسی می‌کنند.
- برای layout عمومی و ورود، لینک «رفتن به محتوای اصلی» اضافه شده است؛ با فوکوس کیبورد نمایان می‌شود و به احترام `prefers-reduced-motion` انیمیشن آن حذف می‌شود.
- هدر صفحه‌های مدرس‌ها و فروشگاه با الگوی معرفی صفحات عمومی یکسان شده تا سلسله‌مراتب بصری نزدیک‌تر باشد.
- فیلتر دسته‌بندی فروشگاه اکنون وضعیت فیلتر، عنوان دسته و راه روشن پاک‌کردن فیلتر را نشان می‌دهد.
- لینک فروشگاه آموزشی در Footer اضافه شده است.
- لینک‌های دسته‌بندی فروشگاه از route نام‌دار Laravel استفاده می‌کنند و به مسیر ثابت متکی نیستند.

## نقشه‌ی فعلی assetها

- `resources/views/layouts/app.blade.php` و `resources/views/layouts/auth.blade.php` از `resources/css/home.css` و `resources/js/home.js` استفاده می‌کنند.
- `home.css` نقطه‌ی ورود Tailwind است، design tokens عمومی، کامپوننت‌ها، Hero، تقویم و `public-experience.css` را وارد می‌کند. `public-experience.css` استایل‌های صفحه‌های کاتالوگ/مجله را scope می‌کند تا به layout نقش‌ها نشت نکند.
- `home.js` رفتار عمومی، Alpine و Hero را راه‌اندازی می‌کند. فعلاً یک bundle مشترک برای صفحه‌های عمومی و ورود استفاده می‌شود؛ استخراج bundleهای جدا باید مرحله‌ی مستقل باشد تا style tokenها، navbar/footer، تقویم و کلاس‌های Tailwind ناخواسته حذف نشوند.

## مواردی که عمداً دست‌نخورده مانده‌اند

1. سِیدرهای جاری Commerce و Learning و داده‌های حساب‌های نمونه؛ جایگزینی هم‌زمان آن‌ها ریسک تغییر semantics و اطلاعات سفارش‌ها را دارد.
2. پیش‌نمایش جداگانه‌ی `unified-dashboard-redesign-demo`: مقادیرش فرضی‌اند و نباید وارد داشبوردهای عملیاتی شوند.
3. جداکردن `home.css` بزرگ به entrypointهای چندگانه. قبل از جابه‌جایی باید وابستگی‌های selectorهای navbar/footer و CSS variables مشخص شوند و تست‌های build و رگرسیون اجرا شوند.


## مشاهده‌ی محتوای نمایشی روی سرور تست

این سِیدر، محتوای نمایشی عمومی (سه دوره‌ی نمونه، سه مدرس نمونه، اسلایدها/بنرها، مقاله‌ها و سه ورک‌بوک) می‌سازد؛ کاربر/سفارش/پرداخت/پیشرفت دانش‌آموز نمایشی نمی‌سازد. آن را فقط روی دیتابیس ایزوله‌ی sheykhan-test اجرا کن، نه روی دیتابیس واقعی production. ابتدا بکاپ دیتابیس بگیر و شاخه/نسخه‌ی حاوی این سِیدر را deploy کن؛ npm run build به‌تنهایی داده تولید نمی‌کند.

با توجه به اینکه سرور تست با APP_ENV=production بالا می‌آید، اجرای کنترل‌شده به این شکل است:

```bash
SHEYKHAN_ENABLE_PUBLIC_EXPERIENCE_SEEDER=true php artisan db:seed --class='Database\\Seeders\\PublicExperienceSeeder' --force
php artisan optimize:clear
```

فلگ فقط برای همان process دستور اول است و در .env ذخیره نمی‌شود. دستور اول عمداً کل DatabaseSeeder را اجرا نمی‌کند. پس از آن صفحه‌ی اصلی، دوره‌ها، مدرس‌ها، مجله و فروشگاه را بررسی کن.
