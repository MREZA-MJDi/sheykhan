# نقشه مهاجرت رابط عمومی شیخان

## هدف و مرز تغییر
- Hero فعلی و اسلایدر دیتابیس‌محور آن حفظ می‌شود.
- Design System عمومی از نخستین سکشن بعد از Hero اعمال می‌شود؛ selectorهای Hero و چالش داخل آن خارج از scope هستند.
- کارت‌های عمومی فقط از سرویس‌های دامنه و رسانه‌های دارای visibility=public و status=active استفاده می‌کنند.
- هیچ route، نقش، قابلیت داشبورد یا گردش‌کار آزمون موجود حذف نمی‌شود.

## وابستگی‌های Backend

| بخش | منبع داده | قرارداد |
|---|---|---|
| Hero | HomeHeroService / HomeHeroSlide | تصویر عمومی، فعال و موجود در Storage |
| آمار | PlatformStatsService | دوره منتشرشده، مدرس تأییدشده، دانش‌آموز فعال |
| دوره‌ها | CourseCatalogService | دوره منتشرشده از آموزشگاه فعال؛ تصویر cover عمومی |
| اساتید | TeacherDirectoryService | حساب فعال، نقش teacher و پروفایل تأییدشده و عمومی |
| کلاس‌ها | LiveClassService | جلسه قابل نمایش با زمان و وضعیت معتبر |
| مقالات | BlogService | مطلب منتشرشده و رسانه عمومی |
| فروشگاه | ProductCatalogService | محصول و دسته فعال با رسانه عمومی |
| محتوای آکادمی | AcademyContentService | محتوای منتشرشده و لینک عمومی |
| افتخارآفرینان | AchievementService | رکورد فعال و رسانه عمومی |
| تجربه خانواده | TestimonialService | تأیید انتشار و رسانه عمومی |
| بنرها | HomeBannerService | بنر فعال آموزشگاه فعال و رسانه عمومی |
| معمای Hero | HeroChallengeService | معمای فعال با چهار گزینه؛ صحت پاسخ فقط سمت سرور |

HomeService تجمیع‌کننده داده صفحه اصلی است. PublicHomeCache مرجع ابطال cache fragmentهاست؛ تغییر محتوای عمومی باید آن را فراخوانی کند.

## مرز معمای عمومی و آزمون آموزشی
- Hero Challenge تعامل کوتاه عمومی برای حل مسئله است و جایگزین آزمون تعیین سطح یا آزمون آموزشی نیست.
- آزمون آموزشی از Exam، Question، ExamAttempt و StudentExamService عبور می‌کند.
- دسترسی آزمون از StudentAccessService و ثبت‌نام/عضویت معتبر دوره و کلاس کنترل می‌شود.
- زمان شروع، مهلت، تعداد تلاش، ارسال پاسخ، تصحیح خودکار و ارجاع سؤال تشریحی برای بازبینی در Backend اعمال می‌شوند.
- پاسخ‌های آزمون و فایل‌های ضمیمه دانش‌آموز خصوصی باقی می‌مانند؛ کارت عمومی نباید آن‌ها را hydrate یا منتشر کند.

## ترتیب اجرا و کنترل ریسک
1. همگام‌سازی شاخه با main با merge commit؛ تاریخچه شاخه حفظ می‌شود.
2. ثبت وابستگی‌های Backend و قرارداد رسانه پیش از تغییر View.
3. افزودن لایه CSS عمومی با scope محدود به public-site و خارج از Hero.
4. نگه‌داشتن ViewModelهای فعلی؛ عدم ساخت داده نمایشی یا URL رسانه حدسی.
5. سخت‌سازی انتخاب معماها تا داده ناقص یک معمای فعال کل ویجت را از دسترس خارج نکند.
6. اجرای تست‌های Feature مربوط به صفحه عمومی، معما، دسترسی آزمون و Build فرانت‌اند.

## معیار پذیرش
- Hero و مسیرهای فعلی آن بدون تغییر رفتاری باقی بمانند.
- سکشن‌های پس از Hero از توکن‌ها، سطح کارت، شعاع، سایه، تایپوگرافی و فاصله مشترک استفاده کنند.
- هیچ media خصوصی در HTML عمومی قرار نگیرد.
- کلید پاسخ معما در پاسخ GET عمومی وجود نداشته باشد.
- گزینه متعلق به معمای دیگر قابل ارسال نباشد.
- آزمون آموزشی فقط برای دانش‌آموز مجاز و در پنجره زمانی معتبر قابل شروع/ارسال باشد.
- تست‌ها و Vite build موفق باشند.
