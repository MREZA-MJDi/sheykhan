# راهنمای اتصال SpotPlayer به شیخان

## هدف و مرز تأیید

این راهنما مسیر عملیاتی اتصال SpotPlayer را تا اولین پخش آزمایشی مشخص می‌کند. وجود route، service و تست‌هایی که پاسخ API را mock می‌کنند، به‌تنهایی اثبات نمی‌کند حساب واقعی SpotPlayer درست تنظیم شده یا لایسنس در پلیر واقعی باز می‌شود. مرحلهٔ سوم فقط پس از آزمایش با اعتبارنامه و دورهٔ واقعیِ مجاز برای تست تأیید می‌شود.

## سه شناسهٔ متفاوت

- **SpotPlayer API key**: کلید سروری برای اتصال شیخان به حساب ناشر SpotPlayer. در پیاده‌سازی فعلی یک مقدار پیکربندی سمت سرور است؛ پیش‌فرض این نیست که برای هر دوره API key متفاوتی لازم باشد.
- **SpotPlayer course ID**: شناسهٔ دوره در پنل SpotPlayer. هر Course در شیخان باید به شناسهٔ خارجی درست خودش متصل شود؛ ID داخلی شیخان را به‌جای آن وارد نکنید.
- **License key**: مجوز اختصاصی صادرشده برای یک دانش‌آموز در یک دوره. این کلید نه API key است و نه course ID.

## چه چیزهایی از مالک حساب/کارفرما لازم است؟

1. دسترسی به پنل مدیریت/ناشر SpotPlayer، نه فقط دسترسی به پلیر وب.
2. API key معتبر با مجوز ساخت لایسنس؛ آن را فقط در محیط امن سرور ثبت کنید، نه در چت، Git یا Pull Request.
3. یک دورهٔ آزمایشی مجاز که در حساب SpotPlayer ساخته شده و فایل/ویدئوی تست قابل پخش دارد، به‌علاوهٔ course ID همان دوره. در صورت نداشتن، اجازهٔ ساخت و آماده‌سازی دورهٔ آزمایشی لازم است.
4. اگر الزام محصول «پخش داخل صفحهٔ شیخان» یا «محدودسازی به دامنهٔ شیخان» است، تأیید روش رسمی Embed و محدودیت دامنه از سوی SpotPlayer. مسیر فعلی شیخان کاربر را به پلیر وب جداگانه می‌فرستد؛ این کار معادل محدودیت دامنه یا Embed نیست.

## روند اجرایی

### ۱. آماده‌سازی دوره در SpotPlayer

1. یک دورهٔ مجزا برای تست در پنل ناشر بسازید.
2. ویدئوی مجاز و غیرحساس تست را طبق روش رسمی SpotPlayer آماده و بارگذاری کنید.
3. course ID را از پنل استخراج کنید و آن را با slug یا ID شیخان حدس نزنید.
4. مشخص کنید پلیر وب برای حساب فعال است یا خیر.

### ۲. نگاشت دوره در شیخان

1. با کاربر دارای permission مدیریت دوره، وارد پنل مدیر شیخان شوید.
2. دورهٔ همتای SpotPlayer را در «دوره‌ها» باز و ویرایش کنید.
3. فیلد «شناسهٔ دوره در SpotPlayer» را با course ID خارجی پر کنید.
4. ذخیره را بررسی کنید؛ شناسهٔ دوره در دیتابیس ستون `courses.spotplayer_course_id` است.

### ۳. تنظیم اعتبارنامهٔ سرور

در محیط آزمایشی خصوصی، در فایل env همان سرور:

~~~dotenv
SPOTPLAYER_API_KEY=<API_KEY_FROM_PROVIDER>
SPOTPLAYER_MODE=test
SPOTPLAYER_MAX_ACTIVE_DEVICES=1
SPOTPLAYER_WEB_APP_DEVICES=1
SPOTPLAYER_WEB_PLAYER_SCRIPT=https://app.spotplayer.ir/assets/js/app-api.js?3c52cbebf58fefff5df91e509879fc66
~~~

این مقادیر را در repository، log عمومی، فرانت‌اند یا پیام‌رسان commit/ارسال نکنید. بعد از تغییر متغیرهای محیطی، config cache سرور را طبق دستورالعمل عملیاتی پروژه تازه‌سازی کنید. حالت `production` را تا زمان اتمام تست واقعی و تأیید مالک حساب فعال نکنید.

### ۴. اجرای تست‌های خود شیخان

~~~bash
php artisan test --filter=SpotPlayerIntegrationTest
php artisan test --filter=OwnerCourseAccessTest
~~~

این تست‌ها مسیر موفق، لایسنس تکراری، رد دسترسی دانش‌آموز غیرمجاز، تنظیمات ناقص، نبود نگاشت دوره، پاسخ نامعتبر، خطای HTTP، host نامعتبر برای download URL و ذخیره‌نشدن API key در خروجی صفحه را کنترل می‌کنند. تست‌های خودکار از پاسخ mock استفاده می‌کنند؛ آن‌ها را به‌عنوان تست واقعی provider گزارش نکنید.

### ۵. تأیید زندهٔ مرحلهٔ سوم

وقتی API key و دورهٔ آزمایشی فراهم شد:

1. قبل از تست، مطمئن شوید `SPOTPLAYER_MODE=test` است و ویدئو حاوی اطلاعات حساس واقعی نیست.
2. یک حساب دانش‌آموز تست با دسترسی معتبر به Course انتخاب کنید.
3. از صفحهٔ دوره «دریافت لایسنس» را بزنید؛ در log سمت سرور، secret یا license key کامل را چاپ نکنید.
4. در دیتابیس تأیید کنید برای همان student/course فقط یک رکورد فعال ساخته شده و مقدار license key در DB به‌صورت رمزگذاری‌شده ذخیره شده است.
5. از صفحهٔ دوره در شیخان، پخش داخل همان صفحه را اجرا کنید؛ پخش، seek، خطاها و واترمارک را در مرورگرهای هدف بررسی کنید. مسیر وب‌پلیر از API رسمی SpotPlayer استفاده می‌کند و نیازی به کپی‌کردن دستی کلید در پلیر جداگانه ندارد.
6. با حساب فاقد Enrollment/دسترسی، هم درخواست صدور لایسنس و هم endpoint همگام‌سازی کوکی پلیر را امتحان کنید؛ هر دو باید رد شوند و endpoint نباید به SpotPlayer درخواست خارجی بفرستد.
7. محدودیت دستگاه را فقط با روش رسمی پنل و روی دستگاه‌های مجاز تست کنید. از نتیجهٔ تنظیمات request به‌تنهایی فرض نکنید محدودیت از طرف provider enforce شده است.
8. نتیجه را همراه زمان، شناسهٔ دورهٔ آزمایشی (بدون secret) و شواهد non-sensitive ثبت کنید.

اگر API key وجود ندارد یا پاسخ واقعی متفاوت است، مرحلهٔ سوم «در انتظار دسترسی provider» می‌ماند. API یا course ID نمونهٔ تست را به‌عنوان اطلاعات Production وارد نکنید.

## آنچه فعلاً پیاده‌سازی شده و نشده

- Service سمت سرور برای درخواست صدور لایسنس، بررسی مجوز Course و اعتبارسنجی پاسخ provider وجود دارد.
- کلید API در config سمت سرور قرار می‌گیرد؛ کلید لایسنس در مدل با cast رمزگذاری‌شده ذخیره می‌شود.
- صفحهٔ دوره از Web API رسمی SpotPlayer برای پخش داخل خود شیخان استفاده می‌کند. endpoint همگام‌سازی کوکی با نام `SPOTPLAYER_X`، دسترسی همان دانش‌آموز به همان دوره را کنترل می‌کند و فقط به `https://app.spotplayer.ir/` درخواست HEAD می‌فرستد.
- کلید API ناشر فقط در سرور می‌ماند. کلید لایسنس برای اجرای `SpotPlayer.Open` به مرورگر فرستاده می‌شود و ممکن است در ابزار توسعهٔ مرورگر دیده شود؛ در UI به‌صورت فیلد متنی نمایش داده نمی‌شود. محدودیت دستگاه و واترمارک باید در لایسنس و پنل ناشر فعال و آزمایش شوند.
- پخش داخل شیخان پیاده‌سازی شده، اما پخش واقعی با حساب ناشر، کیفیت شبکه از اپراتورهای ایران، و رفتار مرورگرهای هدف تا زمان تست زنده تأیید نشده‌اند. این پیاده‌سازی به‌تنهایی تضمین قفل‌شدن دامنه یا جلوگیری مطلق از ضبط صفحه نیست.
- لایسنس موجود برای student/course دوباره استفاده می‌شود. ابطال یا محدودسازی خودکار لایسنس در SpotPlayer هنگام لغو Enrollment و فرآیند جابه‌جایی دستگاه باید جداگانه طراحی و آزمایش شود.
