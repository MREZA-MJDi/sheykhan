# ممیزی و بازآرایی پنل مدیر آموزشگاه

- تاریخ شروع: ۱۴۰۵/۰۸/۱۹
- شاخه کاری: `refactor/owner-admin-dashboard-audit-20261110`
- مبنا: آخرین `main` در زمان شروع
- وضعیت انتشار: فقط شاخه کاری؛ ادغام و استقرار انجام نشده است.

## هدف

پنل برای مدیر یا مسئول آموزشگاه که دانش فنی ندارد باید کارمحور، قابل فهم و قابل اعتماد باشد. هر صفحه باید نشان دهد:
- این بخش برای چه کاری است؟
- هر فیلد چه اطلاعاتی می‌خواهد و چرا؟
- داده از کجا می‌آید و به کدام آموزشگاه/دوره/کلاس محدود است؟
- نتیجه، تعداد کل، صفحه فعلی و خطاها چگونه نمایش داده می‌شوند؟
- چه عملیاتی مجاز است و چه اثری روی سوابق دارد؟

## محدوده اولیه شناسایی‌شده

گروه مسیرهای `owner.*` در `routes/web.php` بیش از ۱۰۰ مسیر خواندن/نوشتن دارد. بخش‌های اصلی شامل داشبورد، اعضا، دوره‌ها، کلاس‌ها، حضور و غیاب، برنامه و جلسات آنلاین، تکالیف، آزمون‌ها، منابع آموزشی، محصولات، سفارش‌ها، ارتباط با اولیا، مشاوره، ضبط جلسات، پرداخت مدرس، گزارش‌ها، مالی و اسناد حقوقی است.

SEO specialist باید پوسته و تجربه مستقل خود را حفظ کند؛ این ممیزی قرار نیست آن را به داشبورد Owner برگرداند.

## یافته‌ها و اصلاح‌های انجام‌شده

1. **راه‌اندازی تکراری تب اعضا**
   - `owner-dashboard.js` ماژول مستقل `owner/people-tabs.js` را بارگذاری می‌کرد.
   - `panel-runtime.js` همان تب‌ها را دوباره با `initializeTabs` راه‌اندازی می‌کرد.
   - راه‌اندازی دوم از runtime حذف شد؛ ماژول اختصاصی تب‌ها، رفتار صفحه‌کلید و فوکوس را نگه می‌دارد.

2. **صفحه‌بندی مدرس‌های آرشیوشده**
   - Blade دکمهٔ «نمایش نتایج بعدی» داشت، اما runtime آن را انتخاب یا به آن listener متصل نمی‌کرد.
   - کنترل به قرارداد صفحه‌بندی قبلی/بعدی تبدیل شد که runtime فعلی پشتیبانی می‌کند.
   - پیوند صفحه‌بندی سمت سرور برای fallback بدون JavaScript حفظ شد.

3. **فرم کلاس و فهرست مدرس‌ها**
   - Blade ورودی‌های مدرس را به شکل radio تولید می‌کرد، ولی اسکریپت همان صفحه دنبال checkbox می‌گشت؛ در نتیجه دسترسی به کنترل null و خطای اجرایی محتمل بود.
   - اسکریپت inline از Blade حذف شد.
   - دوره‌ها و مدرس‌ها به‌جای بارگذاری کامل، با جست‌وجوی سروری و صفحه‌های ۲۰تایی دریافت می‌شوند.
   - فقط گزینهٔ انتخاب‌شده برای ویرایش/بازگشت از خطای اعتبارسنجی در HTML اولیه hydrate می‌شود.
   - endpoint گزینه‌ها به نقش/مالکیت آموزشگاه و مجوزهای `classrooms.view` یا `classrooms.manage` محدود است.

4. **فیلتر دوره در فهرست کلاس‌ها**
   - قبلاً تمام دوره‌های آموزشگاه برای یک select بارگذاری می‌شد.
   - اکنون گزینه‌ها هنگام جست‌وجو و به‌صورت صفحه‌ای دریافت می‌شوند؛ فقط دورهٔ انتخاب‌شده در پاسخ اولیه hydrate می‌شود.

5. **فیلتر کلاس در حضور و غیاب**
   - قبلاً تمام کلاس‌های آموزشگاه برای select فیلتر بارگذاری می‌شد.
   - اکنون از endpoint صفحه‌ای گزینه‌ها استفاده می‌شود و فقط کلاس انتخاب‌شده در پاسخ اولیه بارگذاری می‌شود.
   - فهرست اصلی حضور و غیاب همچنان ۲۵ رکورد در هر صفحه دارد و فیلترها حفظ می‌شوند.

6. **آمار تلاش آزمون‌ها**
   - قبلاً همهٔ آزمون‌های آموزشگاه با `withCount('attempts')` hydrate می‌شدند و جمع در PHP انجام می‌شد.
   - اکنون تعداد تلاش‌ها با یک `COUNT` محدود به همان آموزشگاه در SQL محاسبه می‌شود.

7. **ترتیب import در CSS**
   - `@import './panels/owner/admin.css'` پس از بلوک‌های CSS قرار داشت؛ این جایگاه با ترتیب استاندارد `@import` سازگار نبود.
   - import به ابتدای stylesheet منتقل شد.

8. **مجوز داشبورد**
   - aggregate حضور و غیاب فقط وقتی اجرا می‌شود که کاربر مجوز `attendance.view` داشته باشد؛ در غیر این صورت query غیرضروری حذف می‌شود.

## مواردی که هنوز باید ممیزی شوند

- همهٔ صفحه‌های Owner از Controller تا Service/Query تا Blade و JS، نه فقط صفحهٔ اعضا و کلاس‌ها.
- تمام فیلدهای فرم: منبع داده، مقدار اولیه، وابستگی به فیلد دیگر، اعتبارسنجی سمت سرور، خطای هر فیلد و حفظ مقدار قبلی.
- صفحه‌بندی همهٔ فهرست‌ها: تعداد کل، اندازه صفحه، مرتب‌سازی، فیلتر، جست‌وجو، URL قابل بازگشت و fallback بدون JavaScript.
- queryهای بدون limit یا با eager-loading پرهزینه؛ از جمله بررسی دقیق `liveCandidates` در `OwnerClassroomService::show` که فعلاً همهٔ جلسه‌های گذشته با وضعیت scheduled/live را hydrate می‌کند و باید با توجه به قواعد پایان جلسه اصلاح شود.
- هم‌پوشانی CSS، ترتیب cascade، استایل‌های inline، selectorهای !important و تفاوت ظاهر بین صفحات.
- رفتارهای تکراری JS و اسکریپت‌های inline در Blade؛ انتقال فقط بعد از تعیین مالکیت رفتار و جلوگیری از اجرای دوباره.
- استخراج Blade componentهای واقعی برای فیلد، راهنما، خطای فرم، وضعیت خالی، جدول، فیلتر و صفحه‌بندی؛ بدون ساختن یک component غول‌آسا یا حذف سفارشی‌سازی لازم هر صفحه.
- آزمون مجوز نقش + مالکیت/عضویت آموزشگاه، فرم‌ها، عملیات وابسته، خطاهای 403/404/422/500 و تست رگرسیون.
- بررسی indexها و EXPLAIN و فشار ۱۰۰۰/۱۰٬۰۰۰ رکورد برای مسیرهای پرترافیک.

## وضعیت آزمون

این تغییرها هنوز در محیط اجرایی پروژه با PHPUnit، build فرانت‌اند و مرورگر اجرا نشده‌اند. وضعیت سبز CI هم برای commitهای این شاخه تأیید نشده است؛ بنابراین هیچ‌کدام را «تست‌شده در production» تلقی نکنید. پیش از ادغام باید build، تست‌های مرتبط و ممیزی کامل صفحات اجرا شوند.

## قواعد بازآرایی

- مجوزها، مالکیت آموزشگاه و scope داده‌ها در سرور باقی می‌مانند؛ مخفی‌کردن دکمه مجوز محسوب نمی‌شود.
- برای گزینه‌های بزرگ از endpoint صفحه‌ای استفاده می‌شود؛ برای داده‌های کوچک مرجع، بارگذاری کامل قابل قبول است.
- تبدیل کورکورانهٔ همهٔ `get()`ها به pagination ممنوع است؛ ابتدا باید نیاز واقعی UI و رابطهٔ داده مشخص شود.
- component فقط وقتی مشترک می‌شود که قرارداد ورودی/خروجی و رفتار آن واقعاً بین صفحات یکسان باشد.
- صفحه‌های Owner و SEO specialist پوسته‌های مستقل خود را حفظ می‌کنند.
- تا پایان ممیزی و تست رگرسیون، ادغام در `main` انجام نمی‌شود.
